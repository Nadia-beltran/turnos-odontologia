# Handoff C-04: tenancy y auditoría base

## Qué se hizo

- **Migraciones** `V2__tenancy.sql` (`consultorio`, `usuario`, `sillon`) y `V3__auditoria.sql` (`auditoria` append-only con trigger). `V1__extensiones.sql` no cambió.
- **`ar.turnos.shared.tenancy`**:
  - `TenantContext`: consultorio del hilo, con `ejecutarCon` y `comoSistema` (cada uno con `Supplier` y `Runnable`), `actual()`, `requerido()` y `esModoSistema()`.
  - `BaseTenantEntity`: filtro `tenant` de Hibernate (`autoEnabled`, `applyToLoadByKey`) y guardas `@PrePersist`/`@PreUpdate`/`@PreRemove`.
  - `ConsultorioActualResolver` y `ModoSistemaResolver`: parámetros del filtro.
  - `TenantContextAusenteException` y `TenantViolationException`.
- **`ar.turnos.auditoria`**:
  - `Auditoria` (entidad `@Immutable`) y `ActorTipo`.
  - `ActorAuditoria` y `ActorAuditoriaProvider` (bean por defecto `SISTEMA`; C-06 aporta el suyo).
  - `AuditService.registrar(accion, entidad, entidadId, datos)`.
- **Tests**: `AbstractTenantIsolationTest` (reutilizable), `EntidadPruebaTenant` y la migración de test `db/testmigration/V1000__prueba_tenant.sql` (no se empaqueta).
- **No se crearon** las entidades `Consultorio`, `Usuario` ni `Sillon` (son de C-06).

## Cómo se verificó

`./gradlew build` en `backend/` con Docker/Testcontainers (PostgreSQL 15): 45 tests, 0 fallos, 0 omitidos. `build/resources/main/db/` solo contiene `migration`.

Hallazgos de Hibernate 7.4.15, confirmados con tests:

- `:modoSistema` con `resolver` funciona.
- `applyToLoadByKey` hace que `find()` de un id ajeno devuelva `null`.
- El filtro **sí** se aplica a un UPDATE masivo en JPQL.

## Cómo extender la suite de aislamiento

Cada ficha crea `XxxAislamientoIntegrationTest extends AbstractTenantIsolationTest`, usa `consultorioA()`, `consultorioB()` y `comoConsultorio(id, () -> ...)`, y repite listado propio, búsqueda por id ajeno, alta, modificación ajena y consulta sin contexto. Modelo: `TenantIsolationIntegrationTest`.

## Cuándo usar `comoSistema`

Solo cuando el consultorio todavía no se conoce: login por email (C-06), token de gestión u oferta por hash (C-15 y C-17), procesos que recorren consultorios (C-05 y C-23). Pasar a `ejecutarCon` apenas se conozca. Cada uso se revisa en el PR (se encuentra buscando `comoSistema(`).

## Regla de las consultas nativas

El filtro de Hibernate **no** se aplica a SQL nativo: toda consulta nativa sobre tablas de negocio incluye `consultorio_id = :consultorioId` con `TenantContext.requerido()`. C-05 (`FOR UPDATE SKIP LOCKED`) es el primer caso.

## Preguntas abiertas del diseño

1. `auditoria.datos` puede contener datos personales (RN-SG-02 vs. RN-SG-06). Por defecto se guardan en la tabla y nunca en el log. Decide el equipo antes de C-12 y C-19.
2. IP real detrás del reenvío `/api/*`: se usa `getRemoteAddr()`; las cabeceras reenviadas quedan para C-03.
3. Respuesta HTTP ante una violación de tenancy: hoy cae en el 500 genérico. Propuesta para C-06 y C-08: 404.
4. `@TenantId` en lugar de `@FilterDef`: se mantiene `@FilterDef` (KB 08). Cambiarlo requiere una nueva DD.
5. Métricas agregadas de `ADMIN_SAAS` (C-23): el modo sistema no impide leer datos de pacientes por sí solo.

## Notas para quien revise

- El bean por defecto de `ActorAuditoriaProvider` usa `@ConditionalOnMissingBean` en una `@Configuration` normal. Con el bean de C-06 conviene confirmar que reemplaza al por defecto (el orden de registro puede importar).
